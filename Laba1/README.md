# Лабораторная работа №1 — Программа с графическим пользовательским интерфейсом

Векторный редактор на чистом Win32 API + GDI (язык C, один файл `main.c`).

## Задание (из методички)

> Рисование в окне с помощью мыши. Изображение должно состоять из прямых, ломаных,
> прямоугольников, эллипсов, многоугольников, текстовых надписей. Сохранение рисунка
> на диск в векторном формате — в виде enhanced-метафайла. Загрузка картинки с диска
> и продолжение рисования. Перемещение (Pan) и масштабирование (Zoom) рисунка с помощью
> колесика мыши (Pan — Wheel и Shift+Wheel, Zoom — Ctrl+Wheel и Ctrl+Shift+Wheel).
> Печать любой прямоугольной части векторного изображения.

## Сборка и запуск

```
build.bat
Laba1.exe
```

или вручную:

```
gcc main.c -o Laba1.exe -mwindows -municode -lgdi32 -lcomdlg32
```

Нужен MinGW-w64 (gcc). Библиотеки: `gdi32` — графика и метафайлы, `comdlg32` —
стандартные диалоги «Открыть/Сохранить», «Цвет», «Печать».

## Как пользоваться

| Действие | Как |
|---|---|
| Выбрать инструмент | меню **Инструмент** или клавиши `1`…`7` |
| Прямая / прямоугольник / эллипс | нажать левую кнопку, тянуть, отпустить |
| Ломаная / многоугольник | клики левой кнопкой ставят вершины, правая кнопка (или `Enter`) — завершить, `Esc` — отменить набор |
| Текстовая надпись | клик задаёт точку, дальше набор с клавиатуры, `Enter` — зафиксировать, `Esc` — отменить |
| Цвет | меню **Вид → Цвет...** |
| Отменить последнюю фигуру | `Ctrl+Z` |
| Сохранить в EMF | `Ctrl+S` |
| Открыть EMF | `Ctrl+O` |
| Печать части рисунка | инструмент **Область печати** (`7`), выделить прямоугольник, затем `Ctrl+P` |

Колесо мыши:

| Комбинация | Действие |
|---|---|
| `Wheel` | Pan по вертикали |
| `Shift+Wheel` | Pan по горизонтали |
| `Ctrl+Wheel` | Zoom, шаг 10% |
| `Ctrl+Shift+Wheel` | Zoom, крупный шаг 50% |

Масштабирование идёт «вокруг курсора»: точка рисунка под указателем остаётся на месте.

## Как это устроено

### 1. Модель документа

Рисунок хранится как массив структур `Shape` (тип фигуры, цвет, массив вершин,
текст). Координаты вершин — **мировые**, то есть не зависят от текущего масштаба
и прокрутки. Именно поэтому одни и те же данные без пересчёта годятся и для экрана,
и для метафайла, и для принтера.

### 2. Pan/Zoom через режим отображения GDI

Ручного пересчёта «мир → экран» в коде нет. Вместо этого перед рисованием
вызывается `ApplyView()`, которая настраивает контекст устройства:

```c
SetMapMode(hdc, MM_ANISOTROPIC);
SetWindowExtEx  (hdc, 1000, 1000, NULL);            // знаменатель
SetViewportExtEx(hdc, 1000*zoom, 1000*zoom, NULL);  // числитель  -> Zoom
SetWindowOrgEx  (hdc, org.x, org.y, NULL);          // сдвиг      -> Pan
```

GDI применяет формулу `dev = (log − windowOrg) · viewportExt / windowExt`, так что
все последующие вызовы (`LineTo`, `Rectangle`, `Ellipse`, `TextOutW`,
`PlayEnhMetaFile`) принимают мировые координаты. Обратное преобразование
«экран → мир», нужное для обработки кликов, делает функция `DPtoLP` — см. `ToWorld()`.

### 3. Сохранение в enhanced-метафайл

```c
HDC emf = CreateEnhMetaFileW(refDC, path, &frameRect, description);
DrawDocument(emf);                    // те же вызовы GDI, что и на экране
HENHMETAFILE h = CloseEnhMetaFile(emf);
DeleteEnhMetaFile(h);                 // файл на диске уже записан
```

`CreateEnhMetaFile` возвращает особый контекст устройства: всё нарисованное в него
не растеризуется, а записывается в файл списком команд GDI — это и есть векторный
формат. `frameRect` задаёт габариты картинки в сотых долях миллиметра, поэтому
габариты рисунка в пикселях пересчитываются через `GetDeviceCaps(HORZSIZE/HORZRES)`.

В метафайл пишем при обычном масштабе 1:1 — текущий Zoom окна на содержимое файла
не влияет.

### 4. Загрузка и продолжение рисования

```c
HENHMETAFILE h = GetEnhMetaFileW(path);
GetEnhMetaFileHeader(h, sizeof(hdr), &hdr);   // hdr.rclBounds - габариты
```

Загруженный метафайл становится «фоном» документа и при каждой перерисовке
воспроизводится вызовом `PlayEnhMetaFile(hdc, bg, &bgRect)`. Новые фигуры
рисуются поверх него, а при следующем сохранении фон и новые фигуры записываются
в один новый метафайл — так и получается продолжение рисования. Разбирать чужой
метафайл обратно на фигуры (`EnumEnhMetaFile`) для этого не требуется.

### 5. Печать прямоугольной части

Инструмент «Область печати» задаёт прямоугольник в мировых координатах.
При печати:

1. `PrintDlgW` с флагом `PD_RETURNDC` даёт контекст устройства принтера;
2. масштаб подбирается как `min(ширина_листа/ширина_области, высота_листа/высота_области)`
   — фрагмент вписывается в лист без искажения пропорций;
3. тот же `MM_ANISOTROPIC`, что и на экране, только начало координат — угол
   выделенного прямоугольника;
4. `IntersectClipRect` отсекает всё, что вне выделения;
5. `StartDoc` → `StartPage` → `DrawDocument` → `EndPage` → `EndDoc`.

Если ничего не выделено, печатается весь рисунок целиком.

### 6. Отрисовка окна

`WM_PAINT` рисует не прямо в окно, а в теневой bitmap (`CreateCompatibleDC` +
`CreateCompatibleBitmap`), который затем копируется в окно одним `BitBlt`.
Вместе с `WM_ERASEBKGND`, возвращающим 1, это убирает мерцание при рисовании
«резиновой нити».
