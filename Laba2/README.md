## 4. Как это устроено (подробное объяснение)

Вся работа построена вокруг трех концепций системного программирования Windows:
1. **Проецирование файлов в память (Memory-Mapped Files)**.
2. **Динамически загружаемая библиотека (DLL)**.
3. **Совместное использование памяти несколькими процессами (Shared Memory)**.

---

### 4.1. Структура базы данных в памяти

База данных хранится в оперативной памяти в виде простой структуры языка C ([`phonedb.h`](file:///home/pavel/My/3kurs/SP/Laba2/phonedb.h)):

```c
typedef struct {
    char phone[32];       // Телефон (+375 17 200-11-22)
    char surname[48];     // Фамилия (Иванов)
    char name[32];        // Имя (Иван)
    char patronymic[32];  // Отчество (Иванович)
    char street[64];      // Улица (пр-т Независимости)
    char house[16];       // Дом (10)
    char corpus[16];      // Корпус (1)
    char flat[16];        // Квартира (42)
} Record;

typedef struct {
    int count;                   // Текущее число записей
    Record records[MAX_RECORDS]; // Массив записей прямо в памяти
} Database;
```

**Почему это удобно:**  
Вся база данных — это одна непрерывная область памяти размером `sizeof(Database)`.  
Чтобы обратиться к $i$-й записи, не нужно читать диск блоками: мы просто пишем `db->records[i]`.

### 4.2. Как работает проецирование файла в память

В традиционном подходе программа вызывает `ReadFile()` и копирует данные из файла в буфер в ОЗУ.  
При **проецировании файла в память** ядро операционной системы отображает файл на диске напрямую в виртуальное адресное пространство процесса.

В коде DLL ([`phonedb.cpp`](file:///home/pavel/My/3kurs/SP/Laba2/phonedb.cpp)) это делается ровно четырьмя системными вызовами WinAPI:

#### Шаг 1: `CreateFileA` — открытие/создание файла
```c
g_hFile = CreateFileA(
    "phone_book.db",
    GENERIC_READ | GENERIC_WRITE,
    FILE_SHARE_READ | FILE_SHARE_WRITE, // ВАЖНО: разрешаем другим процессам одновременный доступ
    NULL,
    OPEN_ALWAYS,                        // открыть существующий или создать новый
    FILE_ATTRIBUTE_NORMAL,
    NULL
);
```
Флаги `FILE_SHARE_READ | FILE_SHARE_WRITE` критически важны: они сообщают Windows, что файл могут открывать сразу несколько процессов одновременно.

#### Шаг 2: Установка размера файла
```c
SetFilePointer(g_hFile, sizeof(Database), NULL, FILE_BEGIN);
SetEndOfFile(g_hFile);
```
Файл на диске расширяется до размера структуры `Database`.

#### Шаг 3: `CreateFileMappingA` — создание объекта проецирования
```c
g_hMapping = CreateFileMappingA(
    g_hFile,
    NULL,
    PAGE_READWRITE,
    0,
    sizeof(Database),
    "Local\\MinskPhoneSharedMapping" // ИМЯ ОБЪЕКТА
);
```
Здесь ядро Windows создает специальный объект ядра — **File Mapping**.  
Параметр `"Local\\MinskPhoneSharedMapping"` задает **глобальное имя** этого объекта в системе.

#### Шаг 4: `MapViewOfFile` — получение указателя на память
```c
g_db = (Database*)MapViewOfFile(
    g_hMapping,
    FILE_MAP_ALL_ACCESS,
    0,
    0,
    sizeof(Database)
);
```
Функция возвращает обычный указатель `void*`, который мы приводим к `Database*`.  
С этого момента работа с файлом на диске выглядит как обычная работа с переменной в оперативной памяти:
- Чтение: `printf("%s", g_db->records[0].surname);`
- Запись: `strcpy(g_db->records[0].surname, "Петров");`
- Изменения автоматически сбрасываются ядром ОС на диск!

#### Шаг 5: Закрытие при выходе (`DbClose`)
```c
UnmapViewOfFile(g_db);
CloseHandle(g_hMapping);
CloseHandle(g_hFile);
```

### 4.3. Как две копии программы работают с одной памятью

Это ключевое требование методички:  
*«Несколько копий программы должны работать с одной и той же базой данных в памяти»*.

Вот как это происходит:

```
[ Процесс 1: app.exe ]                         [ Процесс 2: app.exe ]
          |                                              |
    CreateFileA                                    CreateFileA
 (FILE_SHARE_READ/WRITE)                        (FILE_SHARE_READ/WRITE)
          |                                              |
 CreateFileMappingA                             CreateFileMappingA
("Local\\MinskPhoneSharedMapping")             ("Local\\MinskPhoneSharedMapping")
          |                                              |
  Windows создает объект                       Windows видит ТОТ ЖЕ объект!
          |                                    (GetLastError == ERROR_ALREADY_EXISTS)
          |                                              |
    MapViewOfFile                                  MapViewOfFile
          \                                              /
           \                                            /
            v                                          v
      +------------------------------------------------------+
      |   ЕДИНАЯ ОБЛАСТЬ ФИЗИЧЕСКОЙ ПАМЯТИ В ЯДРЕ WINDOWS    |
      |             (Общая структура Database)               |
      +------------------------------------------------------+
                                |
                      Сброс страниц на диск
                                v
                     Файл: phone_book.db
```

1. **Первый запуск `app.exe`**:
   - Вызывает `CreateFileMappingA` с именем `"Local\\MinskPhoneSharedMapping"`.
   - Windows создает новый объект проецирования в памяти.
   - `GetLastError()` возвращает `0`. Программа выводит:  
     `[ИНФО] Запущена ПЕРВАЯ копия программы.`

2. **Второй запуск `app.exe` (в другом окне консоли)**:
   - Вызывает `CreateFileMappingA` с тем же самым именем `"Local\\MinskPhoneSharedMapping"`.
   - Windows видит, что объект с таким именем уже существует, и возвращает дескриптор **того же самого участка памяти**.
   - `GetLastError()` возвращает `ERROR_ALREADY_EXISTS`. Программа понимает:  
     `[ИНФО] Обнаружена запущенная копия программы! Подключено к общей памяти.`

3. **Результат**:
   - Оба процесса указывают на **одни и те же физические страницы памяти** в ОЗУ.
   - Если в первом окне нажать `1` (Загрузить из `phones.txt`), то во втором окне достаточно нажать `2` (Показать записи) — и данные появятся там мгновенно!

### 4.4. Как устроена динамическая библиотека (DLL)

Требование: *«Расположить ядро БД и функции поиска данных в DLL-библиотеке»*.

- Код ядра БД скомпилирован в отдельный файл `PhoneDb.dll`.
- Функции экспортируются с помощью стандартного макроса:
  ```c
  #ifdef PHONEDB_EXPORTS
  #define PHONEDB_API __declspec(dllexport)
  #else
  #define PHONEDB_API __declspec(dllimport)
  #endif
  ```
- Для предотвращения искажения имен компилятором C++ используется блок `extern "C"`.
- Консольное приложение `app.exe` линкуется с `libPhoneDb.a` и вызывает функции:
  - `DbOpen()` — инициализация проекции;
  - `DbClose()` — освобождение ресурсов;
  - `DbLoadFromText()` — чтение `phones.txt`;
  - `DbGetCount()` — получение количества записей;
  - `DbGetRecord()` — получение записи по индексу;
  - `DbSearch()` — поиск.

### 4.5. Как устроен гибкий поиск (`DbSearch`)

Поиск реализован в функции `DbSearch` ([`phonedb.cpp`](file:///home/pavel/My/3kurs/SP/Laba2/phonedb.cpp#L182)):

1. **Поиск без учета регистра**:
   Строка запроса и поля записей переводятся в нижний регистр функцией `ToLowerUtf8` (использует системный вызов Windows `CharLowerBuffW`, что гарантирует корректную работу с русскими буквами `А-Я` и `а-я`).
2. **Поиск по подстроке**:
   Используется функция `strstr`. Если мы ищем `"иван"`, то найдутся и `"Иванов"`, и `"Иванович"`.
3. **Режимы**:
   - `fieldIndex == -1` (**умный поиск**): строка ищется сразу по всем полям (телефон, фамилия, имя, отчество, улица, дом).
   - `fieldIndex == 0` : только по номеру телефона.
   - `fieldIndex == 1` : только по фамилии.
   - `fieldIndex == 4` : только по улице.

## 6. Шпаргалка к защите (Вопросы преподавателя и ответы)

#### Вопрос 1: Что такое Memory-Mapped File (проецирование файла в память)?
> **Ответ:** Это механизм операционной системы, который связывает файл на диске с участком виртуального адресного пространства процесса. После вызова `MapViewOfFile` мы получаем указатель на ОЗУ и работаем с файлом как с обычным массивом структур в памяти, без вызовов `ReadFile` и `WriteFile`. Сброс измененных страниц на диск выполняет сама ОС.

#### Вопрос 2: Как две копии программы работают с одной памятью?
> **Ответ:** За счет **именованного объекта проецирования**. Функция `CreateFileMappingA` принимает строку имени (`"Local\\MinskPhoneSharedMapping"`). Первый процесс создает этот объект в ядре ОС. Когда второй процесс вызывает `CreateFileMappingA` с тем же именем, ядро Windows не создает новый объект, а возвращает дескриптор уже существующего. В результате `MapViewOfFile` в обоих процессах проецирует одну и ту же физическую память.

#### Вопрос 3: Зачем нужны флаги `FILE_SHARE_READ | FILE_SHARE_WRITE` в `CreateFile`?
> **Ответ:** По умолчанию Windows открывает файл в монопольном режиме. Флаги совместного доступа разрешают другим процессам одновременно открывать этот же файл для чтения и записи. Без них вторая копия программы получила бы ошибку «Файл занят другим процессом».

#### Вопрос 4: Чем отличается DLL от статической библиотеки?
> **Ответ:** Статическая библиотека (`.lib` / `.a`) прилинковывается на этапе сборки и ее код физически вшивается в `.exe`. Динамическая библиотека (`.dll`) лежит отдельным файлом и загружается операционной системой в память при запуске программы. Один экземпляр кода DLL в памяти может использоваться несколькими процессами.

#### Вопрос 5: Что делает `__declspec(dllexport)`?
> **Ответ:** Эта директива указывает компилятору и компоновщику поместить функцию в таблицу экспорта DLL (Export Directory), чтобы внешние программы (`app.exe`) могли находить и вызывать эти функции.
